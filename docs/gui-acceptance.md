## 查询规模检查

临时 SQLite 放入 10,000 章、每章 10,000 字节模拟正文。默认分页仅返回 50 条摘要，响应约 8,169 字节；本机一次查询测得 4.67 ms。这个数值是本机冒烟结果，不是性能保证。

## 本轮 GUI 交互优化

- 来源目录、合并目录、组合选章使用统一分页组件；支持首末页、数字页码、输入确认跳转、每页 25/50/100/200 章和当前条目范围。非法页码有明确提示，空目录和加载期间禁用翻页。
- 更改每页数量保留原浏览位置；数据增长不跳回第一页，筛选结果缩减时自动退回有效末页。来源与合并目录均提供顶部/底部翻页，主动翻页定位目录顶部。
- 同页慢查询与轮询合并，不反复取消；切换来源/筛选/页码清掉旧行，过期响应不能覆盖新状态。加载失败可重试。
- 跨页勾选保留选择，并显示本页/总选择数量及半选状态；更改筛选清空选择。
- 预览增加上一章/下一章，按来源的 `(position,id)` 顺序切换；标题、正文与相邻引用来自同一数据库快照。切换失败保留当前正文并可重试，关闭预览取消在途读取。
- 改善首次断连时的加载/空状态、中文请求错误、任务名称与来源入口、非抓取任务的进度文案、未知路由提示和窄屏分页布局。

`frontend/src/pagination.test.ts` 新增 7 项回归，验证确认跳转、非法输入纠正、大目录页码范围、目录变化、每页数量、迟到响应、慢查询及失败重试。`tests/test_gui_pagination.py` 用临时 125 章目录与真实 Chromium 验证三个分页区域、跨页勾选、正文切章、后台完成章节导致的页码回退，以及桌面/390px 窄屏无横向溢出。后端新增相邻章节顺序和首末章边界测试。

本轮全套结果：56 项 Python 测试、14 项前端测试、类型检查、生产构建、compileall 与 diff 检查通过。仍未访问真实小说网站。已重新生成静态资源；使用新相邻章节接口需要重启旧的本地服务并刷新网页。
